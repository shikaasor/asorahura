## Decisions Made
- Split the page into a server file + a sibling client file rather than one file with an inline client sub-component, because Next.js's `"use client"` directive is module-scoped, not function-scoped — a single file cannot export server-only functions (`generateStaticParams`, `generateMetadata`) alongside a `"use client"`-marked interactive component. This is a Rule 1 fix (the plan's literal instruction described a technically impossible pattern); the resulting behavior (server component owns generateStaticParams/generateMetadata, client component owns interactivity) matches the plan's intent exactly.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Split page into server + client files instead of one file with inline "use client" child component**
- **Found during:** Task 1
- **Issue:** The plan's action text asked for the FAQ accordion/CTA to be "isolated into a small inline 'use client' child component within this same file." Next.js's App Router only supports the `"use client"` directive at the top of a module — it applies to the entire file, not to an individual function within it. A single file cannot both export `generateStaticParams`/`generateMetadata` (server-only) and contain a `"use client"`-scoped interactive sub-component.
- **Fix:** Created `OfferingDetailBody.tsx` as a sibling client component file, imported into `page.tsx`. All specified behavior (FAQ accordion pattern, CTA analytics tracking, pricing card structure) is unchanged — only the file boundary differs from the literal plan text.
- **Files modified:** `src/app/automate/[slug]/page.tsx`, `src/app/automate/[slug]/OfferingDetailBody.tsx`
- **Verification:** `npx tsc --noEmit` — zero new errors; `npm test` — 125/125 passing
- **Committed in:** `6f54c86` (Task 1 commit)
